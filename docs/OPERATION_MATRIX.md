| payment.record    | payments:record    | payment.record    |
| refund.request    | refunds:request    | refund.request    |

Proposals also record proposal.create. Approvals consume a proposal exactly once, check its expiry and target version, and commit the mutation with its audit event. REST bearer keys cannot approve. Return restocking additionally requires inventory:adjust. Access management requires an Owner browser session.
